## README quality

- Make the README useful to a first-time visitor: state what the project does, who it is for, and its current status near the top. Keep claims specific and verifiable.
- Provide a tested quick start with prerequisites, exact commands, and the expected result. Keep installation, development, testing, and deployment instructions aligned with current scripts and configuration.
- Organize information for scanning. Explain the main use cases and essential workflows; link to detailed architecture, API, and contributor documentation instead of duplicating it.
- Use current, readable screenshots or diagrams when they materially clarify the product. Give images descriptive alt text, identify the scenario shown, and use links that work for the repository's intended audience.
- Verify every relative link, image path, badge, and command before updating the README. Remove stale, broken, or unsupported claims and badges.
- Include relevant setup, configuration, troubleshooting, contribution, security, and license information; never put secrets or private data in documentation.
- Keep root and subproject READMEs scoped to their actual audiences. Avoid copy-pasting conflicting instructions across multiple files; link to a canonical source where possible.
- Update affected README files in the same change as user-visible behavior, setup, or workflow changes. Review the rendered Markdown and test documented commands when practical.
