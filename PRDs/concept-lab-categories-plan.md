# Concept Lab Categorized Index Implementation Plan

Source issue: [#397](https://github.com/vinitasher/mamaLab/issues/397)
PRD: [concept-lab-categories.md](concept-lab-categories.md)
Owner: Developer
Status: Verified

## Technical Approach

Add an authored, hand-maintained category catalog as a new static module
`js/concept-categories.js`, loaded after `js/wiki.js` and before `js/app.js`.
It defines `CONCEPT_CATEGORIES` (topic -> category), `CONCEPT_CATEGORY_ORDER`,
and `conceptCategory(topic)` with an "Other" fallback. Keeping categories out
of `js/wiki.js` is deliberate: that file is auto-generated by
`scripts/generate-wiki.mjs` and would be overwritten on regeneration.

Refactor `APP.renderConceptCloud()` to keep the existing entry deduplication,
alphabetical sort, and global weight sizing, but partition the flat list into
category groups and render each as a `<section class="concept-group">` with an
`<h3>` heading + count and a wrapped item container. Extract the button markup
into `_conceptCloudItem()` so the existing button contract (class, role,
`data-topic`, `aria-label`, `onclick`) stays intact.

Update `#concept-cloud` from `role="list"` to `role="region"` because it now
contains multiple grouped lists (each inner container keeps `role="list"`).
Add the category styles, the service-worker precache entry, and a cache version
bump.

Apply the same grouping to the child-page Wiki sidebar by extracting the group
partition into `_orderedConceptGroups()` and reusing it in
`APP.renderWikiSidebar()`. The sidebar renders category headings and keeps the
`wiki-topic` buttons (with the active concept highlighted), so `openWiki()`'s
existing active-state toggle continues to work.

## Expected Files And Modules

- `system-design-flashcards/js/concept-categories.js`: new authored category

- `system-design-flashcards/js/app.js`: `_conceptCloudItem()` and
  `_orderedConceptGroups()` extraction, grouped `renderConceptCloud()`, and
  grouped `renderWikiSidebar()`.

- `system-design-flashcards/sw.js`: precache the new module; cache version
  bump to `sdf-v27`.
- `system-design-flashcards/tests/learning-lab-ui.test.mjs`: load the module,
  assert full coverage, index grouping, and sidebar grouping + active state.
- `system-design-flashcards/README.md`: document grouped-by-area behavior.
- `PRDs/concept-lab-categories.md` and `-plan.md`: this feature pair.

## Testing Strategy

- Static/DOM: every bundled topic renders once; every topic has an authored
  category; groups render with the authored headings and counts; buttons retain
  `concept-cloud-size-1..5` and `data-topic`.
- Regression: existing routing, Wiki/Sandbox child-page, and sandbox tests
  continue to pass unchanged.
- Coverage guard: a test fails if a new topic ships without a category,
  surfacing accidental "Other".
- Full suite via `bash check.sh` (syntax checks, audit scripts, `node --test`),
  plus `bash build.sh`.

Verification note: `node` is not installed in the authoring environment, so the
node test suite could not be run locally. JavaScriptCore (`jsc`) parsing of all
modules and a `jsc` functional simulation of `renderConceptCloud()` confirmed
80 buttons across 10 groups with correct counts; a Python cross-check confirmed
all 80 topics are mapped exactly once with no missing, extra, or duplicate
entries. The full `node --test` suite and CI remain the authoritative check.

## Manual And Visual QA

- Open `#/concepts` at desktop and narrow widths; confirm ten grouped sections,
  correct counts, wrapped items, focus rings, and no clipped labels.
- Click items from several categories; confirm `#/concept/<topic>` opens with
  Wiki + Sandbox.
- Confirm an uncategorized topic (if added) appears under "Other".
- Capture desktop and mobile screenshots for the PR.

## Rollout And Compatibility

- The new module is static and versioned with the service worker cache
  (`sdf-v27`).
- No data migration and no API or generation changes. Legacy routes and the
  child page are unchanged.
- Rollback is a git revert; old clients ignore the new module and fall back to
  a single "Other" group.

## Risks

- Categorization is subjective: categories are authored and reviewable; a
  coverage test prevents silent omissions. Maintainers may adjust the map.
- Auto-generated `js/wiki.js` overwrites: categories live in a separate module,
  so regeneration never drops them.
- Visual size could imply authority: unchanged from before — size remains a
  discovery hint only.

## Dependencies

- Existing `WIKI` bundle and the `_conceptEntries()`/`_conceptCloudWeight()`
  helpers.
- No new external service, database, or provider work.

## Unresolved Decisions

- Resolved: keep categories in a separate authored module rather than
  `js/wiki.js`. Rationale: `js/wiki.js` is regenerated by
  `scripts/generate-wiki.mjs` and would lose the field.
- Resolved: use the ten authored categories and their fixed order. Rationale:
  they reflect the bundled concept domains; a "Search" category is deferred
  until search concepts are bundled.
- Resolved: uncategorized topics fall back to "Other" rather than being hidden.
  Rationale: the index must never drop a concept.
